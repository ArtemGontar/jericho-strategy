# JERICHO — подробный план тестирования Unity и iOS

**Редакция:** 1.0 · **Сверено:** 18 октября 2026 года

**Статус выполнения:** протокол подготовлен; проверки на Intel Mac ещё не запускались. Не отмечать тест пройденным до записи фактического результата.

**Связанные документы:** [README](../README.md), [аудит реализации](Implementation_Audit_ru.md), [готовность проекта](Readiness_Audit_ru.md), [чек-лист релиза](Release_Checklist_ru.md), [сборка iOS](iOS_install_ru.md).

## 1. Цель и границы

План проверяет, что проект открывается в Unity на Intel Mac, компилируется, запускается в Play Mode, позволяет начать и завершить настоящую кампанию, сохраняет прогресс, корректно показывает интерфейс и анимации, а при наличии совместимого Xcode собирается для iPhone. Он разделяет автоматические проверки игрового ядра, редакторские проверки Unity, ручную игру на Mac и проверку устройства.

Это план, а не отчёт о выполнении. Пока у тест-кейса нет записи запуска, его статус — **не запускался**. В репозитории нет Unity Test Framework и готовых автоматических Play Mode-тестов: `Packages/manifest.json` сейчас содержит только `com.unity.ugui`. `Tests/CorePlaythrough` — отдельный .NET-набор для детерминированного игрового ядра; его результаты не доказывают, что Unity UI работает.

## 2. Среда Intel Mac

### 2.1. Зафиксированная версия проекта

- В `ProjectSettings/ProjectVersion.txt` закреплена **Unity 6000.0.0f1**. Для базовой приёмки сначала открывать проект именно этой версией; не соглашаться на обновление проекта в новой версии редактора до прохождения базовой проверки.
- Unity 6.0 поддерживает Intel Mac с macOS Big Sur 11 или новее, процессором x64/SSE2 и GPU с Metal. Unity рекомендует минимум 8 ГБ RAM для редактора. Окончательную совместимость сверять по [системным требованиям Unity 6.0](https://docs.unity3d.com/6000.0/Documentation/Manual/system-requirements.html).
- Для iOS проекту нужен установленный через Unity Hub модуль **iOS Build Support**. В требованиях Unity 6.0 указана Xcode 15 или новее. Apple подтверждает, что Xcode 27 работает только на Apple silicon; для Intel Mac нужен Xcode 26 или более ранний. Конкретная доступная версия зависит от macOS на этом Mac. Перед установкой сверить [матрицу macOS/Xcode/SDK Apple](https://developer.apple.com/xcode/system-requirements) и официальное замечание Apple о [Xcode на Intel](https://developer.apple.com/documentation/apple-silicon/porting-just-in-time-compilers-to-apple-silicon).
- Если на установленной macOS нельзя установить совместимый Xcode 15+, можно пройти редакторскую проверку на Mac, а сборку iOS сделать на совместимом облачном Mac или другом Mac. Это не мешает тестированию самой игры в Unity Play Mode.

### 2.2. Сведения о машине для отчёта

Перед тестом сохранить в протокол:

```sh
sw_vers
system_profiler SPHardwareDataType
xcodebuild -version
xcode-select -p
dotnet --info
git rev-parse HEAD
```

В Unity также записать полную версию из **Unity → About Unity**. Если Xcode или .NET не установлены, отметить это как «не применимо» для соответствующего этапа, а не как провал игрового теста.

## 3. Подготовка рабочего клона

1. Установить Unity Hub и Unity **6000.0.0f1**. При планировании iOS-сборки добавить iOS Build Support. Активировать Unity Personal через Hub, если редактор запросит лицензию.
2. Склонировать репозиторий в отдельную папку и проверить ветку/коммит:

   ```sh
   git clone https://github.com/ArtemGontar/jericho-strategy.git
   cd jericho-strategy
   git status --short --branch
   git rev-parse HEAD
   ```

3. В Unity Hub выбрать **Add → Add project from disk** и указать корень клона. При первом открытии дождаться окончания импорта, Package Manager и компиляции. На Intel Mac первый импорт может занять заметное время.
4. Убедиться, что появилась сцена `Assets/Scenes/Main.unity`. Инициализатор `Assets/Game/Editor/ProjectSetup.cs` создаёт её, если её нет, и добавляет в Build Settings. При необходимости вручную вызвать **JERICHO → Создать главную сцену**.
5. В Console снять фильтр, очистить старые сообщения и проверить новые. Ошибок компиляции быть не должно. Предупреждения записать с текстом и контекстом; не скрывать предупреждение только тем, что его уже видели.
6. Запустить редакторские проверки из меню:
   - **JERICHO → Проверить кампанию** — каталог правил, сериализация и пошаговый smoke-прогон кампаний;
   - **JERICHO → Проверить игровые материалы** — доступность атласов, кадров, портретов, районов, иконки и аудио.
7. Запустить сцену `Assets/Scenes/Main.unity` кнопкой Play. В Unity Game view выбрать **Landscape**/широкое соотношение сторон. Проверить как минимум 16:9 и узкий экранный формат телефона. Game view проверяет раскладку UI, но не имитирует производительность iPhone, Taptic Engine или все сенсорные жесты.

Не удалять `Library` и не переимпортировать весь проект при обычном тесте без причины. Не добавлять в Git папки `Library`, `Temp`, `Logs`, `obj`, `bin`, Xcode DerivedData, сертификаты подписи или локальные сохранения.

## 4. Автоматические проверки до ручной игры

Установить .NET 8 SDK, Python 3 и выполнить из корня проекта:

```sh
dotnet --version
dotnet run --project Tests/CorePlaythrough/CorePlaythrough.csproj -c Release
dotnet run --project Tests/CorePlaythrough/CorePlaythrough.csproj -c Release -- replay
python3 Tools/CheckUiBindings.py
```

Ожидается завершение обеих .NET-команд с кодом `0`, итоговая строка полного прогона `PASS: all headless campaign scenarios reached a valid ending`, отдельный успешный replay и успешная статическая проверка bindings. Этот набор покрывает детерминированные кампании, варианты ИИ, достижимость побед, события и экономические/военные регрессии, миграцию/продолжение ядра и контроль целостности replay. Он не тестирует Unity Canvas, нажатия, звук, чтение ресурсов в собранном Player или сенсорное устройство.

`Tools/CheckUiBindings.py` проверяет, что у вызовов `UiKit.Button` есть действие. Это не доказывает, что кнопка видна, доступна, не перекрыта и действительно выполняет ожидаемое действие. В последнем зафиксированном прогоне анализатор находил 88 обычных кнопок и 5 прямых обработчиков; после изменений кода число может измениться.

Для каждого случая завести запись: `ID | статус | дата | среда | результат | ссылка на дефект`. Начальный статус всех кейсов — **Не запускался**.

## 6. Сценарий полного ручного прохождения

Этот сценарий подтверждает игру от первого запуска до конца одной партии. Выполнять на чистом тестовом профиле, чтобы существующие настройки и достижения не меняли результаты.

1. Открыть стартовое меню и записать коммит, версию Unity, формат Game view, культуру, сложность и темп.
2. Выбрать одну культуру, **Standard** сложность и темп **Быстрый** (60 ходов) для укладывания одного ручного прогона в тестовую сессию. Если проверяется баланс/понятность, использовать Standard 80 ходов и записать длительность.
3. Начать новую кампанию; пройти все шаги обучения, выполняя требуемые действия и не переходя вперёд до выполнения условия. Отдельно проверить пропуск любого шага.
4. В первых ходах пройти каждую вкладку; проверить город, распределение ролей, доступное исследование, проект, земельное улучшение, дипломатию и журнал событий.
5. Включить слой еды и производства, осмотреть клетку, затем проверить владение/оборону и вернуться к обычному виду. Переместить доступный отряд; не отдавать ход повторно, пока анимация разрешения хода не завершилась.
6. Основать второй город, если экономические условия позволяют. Следить за продовольствием, населением, здоровьем, казной и доверием; при событии записать выбранное решение и последствие.
7. Создать ручное сохранение в одном слоте; пройти ещё ход; закрыть Play Mode и продолжить кампанию. Затем загрузить ручной слот и сравнить состояние с записанным ходом.
8. Открыть параметры анимаций и повторно посмотреть хотя бы одно строительство/движение на каждом режиме. Послушать меню и музыкальную смену эпох; проверить выключение эффектов.
9. Выбрать активный путь победы и выполнять его условия, не прекращая поддерживать базовую экономику. На карте проверить видимые действия соперников, их стратегическое объяснение и последствия дипломатии/конфликта.
10. Довести партию до экрана активной победы либо лимита ходов. Записать точный исход, ход, длительность партии и seed; проверить финальный отчёт, достижение/титул и возврат в меню.
11. Сохранить диагностический отчёт и приложить его к результату. Для механик, которые не встретились из-за seed, создать отдельную партию, а не утверждать их прохождение по памяти.

Все четыре активных пути победы и разные уровни ИИ уже имеют headless-покрытие. Вручную следует дополнительно пройти минимум один активный путь от интерфейса до финала; при ручной возможности пройти отдельные пути науки, культуры, дипломатии и благополучия.

## 7. Правила регистрации дефектов

### Приоритет дефекта

- **S0 / критический:** потеря сохранений, блокирующий краш, невозможно начать/завершить кампанию, неверно объявляется победитель, основной экран неуправляем.
- **S1 / высокий:** не работает ключевая кнопка/вкладка, ход не завершается, сломаны загрузка или основная механика, неверно рисуются скрытые данные, стабильный UI softlock.
- **S2 / средний:** неправильная раскладка, нечитаемый текст, отсутствующая анимация/звук, редкая ошибка без обхода игрового цикла.
- **S3 / низкий:** мелкая косметика, неточность формулировки, редкий артефакт без влияния на выбор.

### Шаблон дефекта

```text
Заголовок:

Шаги воспроизведения:
Ожидаемый результат:

```

Для Editor log на Mac использовать `~/Library/Logs/Unity/Editor.log`. Перед отправкой сейва или полного лога удалить личные данные/секреты, если они туда попали. Оригинальный слот перед экспериментом с повреждённой копией сохранить.

## 8. Критерии приёмки тестового прогона

Демо считается прошедшим техническую ручную приёмку только после выполнения всех применимых P0-кейсов, прохождения кампании от новой игры до финала, проверки ручного/автоматического сохранения после перезапуска, отсутствия S0/S1 дефектов без обхода и прикреплённых логов/диагностики. P1/P2 вести отдельным списком, не скрывая провалы.

Это не означает готовность к мировому релизу: английская локализация, VoiceOver/экранный диктор, полная информационная изоляция стратегического планировщика ИИ, тесты новичками, производительность на целевых устройствах, подпись и App Store review остаются отдельными воротами из [чек-листа релиза](Release_Checklist_ru.md).
